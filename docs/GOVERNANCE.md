# POG Governance

**Version:** 1.0  
**Status:** Adopted  
**Published:** 2026-08-02

---

# Purpose

This document establishes how the Property Operations Guide (POG) is managed, expanded, and maintained.

POG is intended to be a long-term operational framework that evolves through deliberate, documented improvements rather than ad hoc changes.

---

# Mission

Create an operational framework that enables homeowners and small property owners to manage residential properties using repeatable processes, standardized documentation, and continuous improvement.

---

# Core Principles

Every addition to POG should satisfy one or more of the following:

- Improve operational consistency
- Reduce risk
- Preserve institutional knowledge
- Increase documentation quality
- Simplify maintenance
- Protect privacy
- Improve decision making
- Be reusable across multiple properties

---

# Guiding Philosophy

POG favors:

- Standards over preferences
- Documentation over memory
- Prevention over repair
- Simplicity over complexity
- Continuous improvement over perfection

---

# Change Management

Changes should generally follow this lifecycle:

1. Idea
2. Discussion
3. Decision
4. Documentation
5. Implementation
6. Review

Major architectural changes should be documented using an Architecture Decision Record (ADR).

---

# Documentation Standards

Every permanent document should include:

- Title
- Version
- Status
- Publication Date
- Purpose
- Scope (when applicable)

Documents should be written so they remain understandable years after they are created.

---

# Versioning

Major Version
- Significant structural or architectural changes.

Minor Version
- New content or expanded capabilities.

Patch Version
- Corrections, formatting, or clarification.

Example:

- 1.0
- 1.1
- 1.2
- 2.0

---

# Repository Philosophy

The public repository contains reusable knowledge.

Property-specific operational records belong in private repositories.

Highly sensitive information belongs in secure encrypted storage.

---

# Continuous Improvement

Ideas are encouraged at any time.

Ideas identified during discussions should be captured in the POG Idea Log before they are forgotten.

Not every idea requires immediate action, but every idea deserves to be recorded.

---

# Success Measure

POG succeeds when someone unfamiliar with a property can understand how it is operated simply by reading its documentation.
